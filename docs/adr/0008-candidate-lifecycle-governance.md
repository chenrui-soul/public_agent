# ADR 0008：候选软过期、价值淘汰与可审批压缩治理

- 状态：Accepted
- 日期：2026-08-25

## 决策点

成长候选和正式记忆不断增加后，系统如何在不破坏证据、审批、发布与回滚边界的情况下处理陈旧、
低价值或重复资产，并保证批量任务在并发 Worker、重试和中断后仍然安全恢复。

## 候选方案

| 方案 | 优势 | 劣势 | 适用场景 |
|---|---|---|---|
| 按 TTL 物理删除 | 实现简单，立即释放空间 | 破坏运行证据、审批和谱系，无法解释能力变化 | 不适合生产成长资产 |
| 原地改写或覆盖正式记忆 | 表数量少，替换直接 | 压缩器可绕过重新评测审批，并发回滚无可靠来源状态 | 不采用 |
| 软过期 + 价值评分 + 新建压缩候选 | 审计、保护、幂等和回滚边界完整 | 增加使用统计、关系表、审计表和策略治理成本 | 当前项目 |

## 决策

选择“软过期 + 价值评分 + 新建压缩候选”。

### 1. 软过期，不自动物理删除

`LearningCandidate` 增加 `expires_at`、`protected_until` 和 `expired` 终态。自动过期或低价值淘汰时：

- 候选进入 `expired`；
- 对应正式记忆进入 `expired` 并停止召回；
- 运行、事件、评测、审批、候选正文、正式记忆和来源谱系全部保留；
- `expired` 与 `rejected`、`rolled_back` 一样不阻止同指纹在新证据下重新提出。

物理保留期和法规清除属于独立、高风险的合规归档流程，不复用自动遗忘任务。

### 2. 版本化价值评分与硬保护门禁

首版 `candidate-governance-v1` 组合：最近评测分数 30%、重要度 25%、置信度 20%、召回次数 15%、
召回新鲜度 10%。正式记忆召回在同一事务中原子增加 `recall_count` 并写入 `last_recalled_at`。

以下对象禁止自动过期或淘汰：

- `evaluating`、`awaiting_approval`、`approved`；
- 高风险候选；
- `governance.protected=true` 或 `protected_until` 尚未到期；
- 被非终态合并/压缩候选引用的来源；
- 达到策略重要度或置信度阈值的活跃正式记忆。

执行阶段不能信任扫描快照。仓储重新锁定候选和正式记忆，校验候选版本、状态、召回计数和活跃后代；
任何变化都跳过本次动作，让下一批基于新快照重新决策。

### 3. 有界、幂等、可恢复批处理

扫描按租户、智能体和可选领域过滤，使用不可变 `created_at + id` keyset 游标；批次上限 500，默认 100。
过期和淘汰的幂等键绑定候选 ID、候选版本、动作和策略版本。每个动作写入
`candidate_governance_actions`，保存原因、价值分数、前后状态和安全详情。并发 Worker 通过候选行锁、
版本校验和唯一幂等键收敛，不依赖进程内锁。

### 4. 压缩创建新候选并重新治理

首版 `DeterministicCandidateCompressor` 只接受同作用域、同类型、活跃且每一对都被保守冲突检测器判为
`compatible` 或 `duplicate` 的 2-20 个来源。它选择高重要度、高置信度且更简洁的代表内容，合并运行、
事件和标签证据，生成绑定策略、压缩器和来源版本的确定性候选 ID。

压缩不会原地修改来源。`candidate_lineages` 保存来源候选 ID、版本、发布前状态和关系类型。新候选必须
重新评测并停在 `awaiting_approval`；只有显式批准发布后，来源候选与来源记忆才在同一事务中弃用。
压缩候选回滚时恢复来源发布前状态和召回能力。压缩来源本身若是旧合并候选，新候选只保留本次
`compression` 派生关系，避免同时携带两套直接派生元数据。

## 反选论证

- 不选物理删除：自动评分存在误判可能，删除会让错误不可审计、不可恢复，也会破坏外键谱系。
- 不选仅按 TTL：低频但关键的政策或故障知识可能长期不召回，时间不能单独代表价值。
- 不选只按模型评测分数：离线评测不能代表真实运行使用，且历史模型评分可能发生版本漂移。
- 不选原地压缩：任何压缩器都可能遗漏细节；绕过候选、评测和人工审批会把风险直接带入运行时。
- 不选首版模型压缩 API：当前先建立完整治理、证据和回滚契约，避免收费、超时和供应商错误掩盖核心边界。

## 接受的代价

- 每次正式记忆召回增加一次轻量原子统计写；真实负载需要持续观察数据库写放大与 P95。
- 批次扫描会读取每个候选的最新评测、正式记忆和活跃来源关系，但总量受批次上限约束。
- 确定性压缩器不会生成新的自然语言摘要，只提供可验证的安全基线；更强压缩需实现同一协议并通过领域评测。
- 软过期不释放历史存储空间；后续仍需要独立归档与合规删除策略。

## 撤销条件

- 同步召回统计使检索 P95 或数据库写负载超过目标时，改为 Outbox/异步聚合，但保持快照字段和竞态校验契约。
- 价值评分在领域回归和人工复核中误伤率不可接受时，发布新策略版本并保留旧动作审计，不原地改变历史解释。
- 确定性压缩无法达到信息保留门槛时，接入版本化模型压缩器，但仍只能创建候选并重新评测审批。
- 候选规模使 PostgreSQL keyset、最新评测或谱系查询无法满足 SLA 时，增加汇总表或专用 Worker，不改变 PostgreSQL 事实来源。

## 验证

- 单元测试覆盖过期、低价值评分、全部保护门禁、压缩确定性和派生元数据去嵌套。
- PostgreSQL 集成测试覆盖 keyset、召回统计、并发幂等、软过期、高价值保护、压缩发布和回滚恢复。
- 独立临时数据库验证旧合并 JSON 谱系 keyset 回填、`upgrade → downgrade → upgrade` 和 schema drift。
- 全量 Ruff、Mypy、PostgreSQL Pytest、索引/约束实查和原有示例作为发布门禁。
