# ADR 0004：候选冲突检测、显式合并与独立指纹索引

- 状态：Accepted
- 日期：2026-08-25

## 决策点

候选知识发生语义重复、兼容补充或直接矛盾时，系统应如何治理，并如何让精确去重在 PostgreSQL 中稳定扩展。

## 候选方案

| 方案 | 优势 | 劣势 | 适用场景 |
|---|---|---|---|
| 仅依赖 JSON 指纹去重 | 改动最少 | 需要加载并扫描候选 JSON，无法可靠处理兼容和矛盾 | 小规模原型 |
| 指纹唯一约束并自动覆盖 | 并发去重直接 | 拒绝或回滚后无法重新提出，自动覆盖破坏审批和审计 | 不适合受控成长 |
| 独立索引 + 保守冲突检测 + 显式合并 | 精确查询可索引，冲突可审计，保留人工治理 | 需要额外领域契约和事务处理 | 当前项目 |

## 决策

选择“独立索引 + 保守冲突检测 + 显式合并”。

- `LearningCandidate.fingerprint` 和数据库独立列成为权威值，JSON 副本仅用于兼容与审计。
- 精确重复不产生第二个非终态候选；数据库通过作用域 advisory lock 串行化同指纹创建。
- 默认检测器只在证据足够时判定 `compatible` 或 `contradictory`，不确定时返回 `none`，避免模型式猜测污染治理。
- 沉淀阶段仅记录冲突评估；合并由显式操作触发，创建新候选并重新走评测和人工审批。
- 合并发布时，合并资产激活、来源候选弃用和来源记忆停用在同一 PostgreSQL 事务中完成。
- 合并谱系保存来源候选的发布前状态与版本；合并资产回滚时在同一事务中恢复来源状态和来源记忆。

## 反选论证

- 不选“仅 JSON 指纹”：当前仓储最多加载 500 条再在 Python 中比较，数据量扩大后查询成本和延迟不可控，也无法为冲突治理提供稳定索引入口。
- 不选“唯一约束并自动覆盖”：`rejected`、`rolled_back` 是受控成长中的合法终态，同一知识在证据变化后应能重新提出；自动覆盖也会绕过评测与人工审批。

## 接受的代价

- 规则检测器是保守启发式，不宣称覆盖所有自然语言矛盾；后续可通过同一协议接入领域模型或回归评测器。
- 非唯一索引不能单独阻止竞态，因此候选创建仍需事务级 advisory lock。
- 合并会产生新的候选和评测记录，增加少量存储，但换取完整谱系和可回滚性。

## 撤销条件

- 规则检测器在真实领域语料上的误判率超过评测阈值时，引入领域冲突模型，但保持 `ConflictAssessment` 契约不变。
- 候选规模或冲突检索延迟无法满足目标时，增加语义键、全文或向量召回索引。
- 成长模块拆为独立服务时，将 advisory lock 替换为跨服务幂等键或消息去重机制。

## 验证

- 单元测试覆盖重复、兼容、矛盾、谱系、发布前后状态和反例。
- PostgreSQL 集成测试覆盖独立列查询、并发合并幂等和事务发布。
- Alembic 执行 `upgrade → downgrade → upgrade`，验证旧 JSON 指纹回填和 schema drift。
